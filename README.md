# MacVoy School of Irish Dance — Platform

Rebuild of macvoyirishdance.com: public marketing site + parent portal
(registration, payments, calendars, announcements) + admin CMS for Debbie.

**Stack:** Next.js (App Router) · TypeScript · Tailwind · Supabase (Postgres +
Auth + Storage) · Vercel. Payments via Helcim, email via Loops, errors via
Sentry.

> Full requirements: `MacVoy_Platform_Spec.md` (in your Downloads).

## Status — Phases 1 & 3 ✅

**Foundation**
- Complete database schema with row-level security (`supabase/migrations/`)
- 2026–2027 season, rate card, and all 14 classes seeded
- Supabase auth wiring (browser / server / service-role clients)
- Integration interfaces for Helcim & Loops (stubbed until API keys exist)
- Tuition & installment math (`src/lib/billing/`)

**Auth & registration**
- Login, self-service password reset, logout (`/login`, `/forgot-password`,
  `/reset-password`, `/auth/callback`)
- Per-dancer registration (`/register`): live class list from the current
  season, all §5 fields, 6 waiver checkboxes snapshotted into `consents`,
  add-on selection, quarterly / pay-in-full plan with a live tuition preview
- Registration creates the Supabase Auth login + `family_account` for new
  families, or attaches a new dancer to a logged-in family

**Parent dashboard** (`/dashboard`)
- Overview with next-class / next-payment / unread-announcement cards + dancer list
- **Calendar** — collective (all dancers) and per-dancer month views reading
  from `class_sessions`, filtered by active enrollments; cancelled classes shown
  struck through; auto-updates when the schedule changes
- **Payments** — upcoming scheduled installments + receipt history ("Pay now"
  is disabled until Helcim is connected)
- **Announcements** — archive of announcements targeted at the family (RLS
  enforces the same all/location/class/individual targeting as the send), with
  in-app read tracking (`announcement_reads`), separate from email opens
- Class sessions are generated by `generate_class_sessions()`
  (`0004_generate_sessions.sql`), run automatically for 2026–2027 on db reset

**Admin CMS** (`/admin`, gated by the `admins` table)
- **Seasons & classes** — create seasons (auto-seeds a rate card), edit the rate
  card per season, add/edit class templates; edit a template with **future-only
  session regeneration** (from a chosen date, past untouched); cancel/annotate
  individual sessions (holiday weeks)
- **Families** — list + per-family support view; per dancer: enroll, **remove**,
  **reassign** (tuition auto-recalculates off the rate card), **stop billing**
  (typed-confirm, halts future charges only — never a refund), create **custom
  payment plans**; send a **password-reset email** to the login
- **Announcements** — compose + send with the All / Location / Classes
  (multi-select + select-all) / Individuals targeting picker; saved to the
  archive first, email dispatched via Loops when connected
- **Payments** — CSV export filterable by date range (`/api/admin/payments/export`)

## Local setup

Requires Node 20+ and the [Supabase CLI](https://supabase.com/docs/guides/cli).

```bash
npm install
```

```bash
cp .env.example .env.local
```

### Run the database locally

Starts a local Postgres + Auth + Studio and applies every migration in order:

```bash
supabase start
```

```bash
supabase db reset
```

`supabase start` prints the local API URL, anon key, and service-role key —
paste those into `.env.local` (`NEXT_PUBLIC_SUPABASE_URL`,
`NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`).

Regenerate the TypeScript DB types after any schema change:

```bash
npm run db:types
```

### Run the app

```bash
npm run dev
```

Open http://localhost:3000.

## Making a user an admin (Debbie)

There is no self-serve admin signup. After a user signs up through Supabase
Auth, add their `auth.users.id` to the `admins` table (via Studio or SQL):

```sql
insert into admins (user_id) values ('<auth-user-uuid>');
```

RLS then grants that user full access; everyone else is a parent scoped to
their own family account.

## Open items carried from the spec

- **Late fees** — schema has `payments.late_fee_amount` /
  `late_fee_applied_at`; automation is intentionally **not** wired pending
  Debbie's decision on amount + auto-vs-manual.
- **Tuesday 7:00–8:00 Advanced Soft Shoe** overlaps neighbouring classes —
  seeded as-is, flagged for confirmation.
- **Two 45-minute beginner classes** (Tue 6:00–6:45, Thu 5:30–6:15) have no
  matching rate-card row (card is 30/60/75/90/120). Tuition lookup will miss
  them until a 45-min rate is added or the times adjusted. Flagged in
  `0003_seed.sql`.

## Integrations

- **Sentry** ✅ wired (`sentry.*.config.ts`, `src/instrumentation*.ts`,
  `withSentryConfig` in `next.config.mjs`). Active in production only. Set
  `SENTRY_ORG`/`SENTRY_PROJECT`/`SENTRY_AUTH_TOKEN` for readable stack traces.
- **Loops** ✅ wired (`src/lib/integrations/loops.ts`). Needs the sending domain
  verified and the `LOOPS_TID_*` transactional template ids to actually send.
  Announcement open/click stats aren't available for transactional sends (would
  need Loops Campaigns).
- **Helcim** — interface in `src/lib/integrations/helcim.ts`; charging + webhook
  handler come once the account keys are in and the app is deployed (needs a
  public webhook URL). Card capture will use HelcimPay.js (no raw card data on
  our servers).
